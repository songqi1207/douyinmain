# 视频创作平台重要配置与数据清单

更新时间：2026-08-11

本文档是平台部署、迁移、备份和故障恢复的唯一总清单。任何服务器迁移只有在本文档中的必需资产全部核对通过后，才能视为完成。

## 1. 核心资产基线

平台必须长期保留的正式视频是 **23 条**。

- 这 23 条是平台正式作品或正式展示视频，必须保留原片、网页预览地址、任务 JSON/草稿 JSON 和所属用户/工作流关系。
- 本机 `downloads/reference_workflows` 中的 261 个 MP4 是参考工作流附件、演示素材和历史下载，不等于这 23 条正式视频，不能整包导入“我的作品”。
- 服务器迁移验收必须满足：正式视频数量 = 23、23 条均可播放、23 条均可下载、23 条均能关联到正确任务或正式展示位。
- 23 条正式视频的清单必须包含：序号、标题、工作流代码、任务 ID、所属用户、R2 原片 URL、720P URL、1080P URL、文件大小、SHA-256、创建时间和恢复状态。
- 未拿到 23 条的完整清单前，不得删除旧 R2 对象、导出机本地 MP4、旧数据库或任何迁移备份。

当前恢复状态：**23 条正式视频尚未在新服务器数据库中重建完整关联，迁移未完成。**

## 3. 必需持久化数据

### 3.1 任务数据库

路径：`temp/workflow_app/workflow.sqlite3`

必须保留：

- `jobs`：任务、状态、工作流、用户、计费、结果 URL 和导出设备关系。
- `job_logs`：生成、剪映导出、回传、R2 上传和失败阶段日志。
- `assets`：用户上传素材元数据。

### 3.2 用户和计费数据库

路径：`temp/workflow_app/site.sqlite3`

必须保留：

- `users`、`sessions`：用户账号与会话。
- `user_quotas`、`quota_ledger`、`generation_reservations`：积分余额、流水和冻结记录。
- `registration_applications`：注册审核记录。
- `render_devices`、`render_pairing_codes`：导出机配对状态。
- `video_storage`、`video_preview_unlocks`：正式视频地址、存储计费和 1080P 解锁。
- `workflow_pricing`、`provider_usage_events`：工作流价格和供应商调用记录。
- `favorites`、`resource_events`、`invite_rewards`：用户行为和邀请奖励。

### 3.3 任务结果目录

路径：`temp/workflow_app/results`

必须保留：

- `*-draft-key.json`：剪映草稿生成记录。
- `*-device.mp4`：尚未上传 R2 或 R2 处理失败时的站点原片。
- 被校验拒绝的 JSON：用于分析素材、字幕或主体图片缺失问题。

临时分片目录 `temp/workflow_app/results/.device-uploads` 只用于正在上传的视频；确认任务完成后可以清理，失败任务的本地原片不能因此删除。

### 3.4 R2 正式媒体

正式媒体位于：`https://media.songqi.online/exports/`

每条正式视频通常可能有：

- `*-device-original.mp4`：高清下载原片。
- `*-device-preview.mp4` 或 `*-device-web.mp4`：720P 流畅预览。
- `*-device-preview-1080.mp4`：1080P 网页预览。

R2 对象存在不等于网页可见。必须同时在 `jobs.results_json` 和 `video_storage` 中恢复 URL 关联。

## 6. Windows 剪映导出机

- 当前助手版本：`v1.4.84`。
- 剪映版本：`11.2.5.14310`。
- 助手数据目录：`C:\Users\<用户>\AppData\Roaming\AIVideoCreator`。
- 默认回传缓存：`C:\Users\<用户>\AppData\Roaming\AIVideoCreator\output`。
- 剪映手工重复导出可能产生“文件名 (1).mp4”；助手必须优先按任务 ID 和草稿名匹配，不能误传其他任务的视频。
- 大文件通过 Cloudflare 回传必须使用 5MB 分片，不能恢复成单个大请求。
- 助手发现本地已有 MP4 时应直接补传，不能重复打开剪映导出。

## 8. 23 条正式视频恢复流程

1. 只读列出 R2 `exports/` 全部对象，记录文件名、大小、时间和 ETag。
2. 从旧数据库备份、任务日志、网页历史或导出机缓存中找出 23 个正式任务 ID。
3. 按任务 ID 把原片、720P、1080P 三类对象归组。
4. 生成一份 23 条正式视频 manifest，并计算本地文件 SHA-256。
5. 向新服务器 **合并** `jobs`、`job_logs` 和 `video_storage`，不得直接覆盖现有数据库。
6. 缺少 R2 对象时，从导出机本地 MP4 补传；已有正确对象时只恢复 URL，不重复转码。
7. 使用普通用户和管理员分别核验可见范围、播放、下载、积分和删除权限。
8. 23 条全部验收后，才允许清理重复文件或旧服务器备份。

每天至少备份：

- `workflow.sqlite3` 和 `site.sqlite3` 的一致性快照。
- `.env` 的加密副本。
- 23 条正式视频 manifest 和 R2 对象清单。
- `temp/workflow_app/results` 中尚未进入 R2 的 JSON/MP4。
- 当前 Windows 助手 EXE、版本号和导出机配对说明。

每次服务器迁移必须执行：

1. 停止写入或创建数据库一致性快照。
2. 备份旧服务器 `.env`、数据库和结果目录。
3. 导出 R2 对象清单，不依赖数据库中的 URL 猜测对象是否存在。
4. 在新服务器恢复配置和数据库后再启动服务。
5. 核对用户数、任务数、积分流水数、视频存储数和 23 条正式视频。
6. 测试 Coze、米核、Boltp、SMTP、R2 和剪映助手。
7. 验收完成前保留旧服务器和离线备份。
